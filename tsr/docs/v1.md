# tsr 0.1.0 — implementation and verification

All four commands are implemented: `save`, `list`, `restore` and `doctor`.
Production remains one Python 3.14 module with standard-library runtime
dependencies only. M1 format-1 snapshots remain readable and unchanged.

## Restore implementation

The pure availability rules distinguish exact running identities, pending and
confirmed tsr reservations, missing folders, ambiguous recent-transcript groups,
and scoped uncertainty. The pure planner preserves saved order across windows
and split panes. The curses picker supports window/tab selection, disabled-row
reasons, keyboard navigation, collapse/expand and cancellation.

The effect boundary rechecks selected rows under a bounded exclusive flock,
reserves before launching, appends new tabs sequentially, waits for their shells,
and types safely quoted commands only into those created terminals. It hands
off its own terminal last through chdir/exec. Known launch failures release their
reservation; other rows continue. Current-tab errors preserve successful new
tabs. Pending reservations are renewed during long batches without reviving an
expired lease. The picker holds no lock. Cancellation before Enter leaves state
unchanged; an Enter recheck can update reservation records before returning to
the picker, but never rewrites the snapshot.

Process confirmation uses the S16 evidence: pre-exec PID/start/tty (or a verified
live child) for the current handoff; the newly created terminal association plus
second-resolution start bounds for new tabs. Boot, process start and tty checks
reject stale confirmed identities. These are process associations, not a passive
Codex/pi session-ID interface. Independent launch races remain outside tsr's
coordination guarantee. The Codex daemon query is deferred, not silently enabled.

Decision B remains deferred: frozen format 1 requires nonempty string cwd.
Capture fails and preserves existing snapshots when no reliable folder is
available. Ambiguous caret/control lsof display forms likewise fail safely.

## Review corrections

The subsequent code/documentation review added four regressions, reproduced
their failures and repaired the production paths:

- Reject selecting the same known session twice before any reservation or launch.
  Ambiguous/picker reservations contain no guessed conversation ID.
- Return to the picker when Enter discovers a changed warning, before launching.
- Keep agents on different ttys when their process ancestry overlaps; share the
  same outermost-on-this-tty rule between capture and availability.
- Keep warning/reason text visible when folder names are long. Below 40 × 6,
  require resizing or cancellation before accepting a selection.

The review also corrected the cancellation test to inspect the state directory
actually used by the command, and made the two v1 probe scripts require `--run`.
Their `--help` paths perform no desktop or installation actions. **34 tests pass**
on both tested Python 3.14 installations; the baseline live measurements above
were not rerun during the review. Snapshot format 1 is unchanged.

## Local commands

```sh
cd tsr
uv run tsr doctor
uv run tsr save
uv run tsr list
uv run tsr restore
PYTHONPATH=src python3.14 -m unittest discover -s tests -v
```

First inspect save's confidence and recovery commands. Restart manually only
when ready. Restore in a Ghostty shell; it replaces itself in that shell's child
process and opens the remaining panes as tabs. Default installation/publication
remains owner-managed; README includes local and private-tag installation steps.
