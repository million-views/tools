## S6: document only; never execute a restart

The local dictionary defines `restart` with AppleEvent code `fndrrest`, and an
optional boolean `state saving preference` (`stsv`). Its documentation says omitted
or false always saves state, so the candidate preserves the user's preference:

```applescript
-- DOCUMENTATION ONLY. DO NOT RUN DURING SPIKES.
tell application "System Events" to restart with state saving preference
```

No AppleEvent, privileged command, compiled restart script or actual restart was
attempted. The dictionary alone does not establish no-root execution, prompt
attribution or whether every app gets its expected quit/cancel handling. The
current designed fallback is `Saved. Restart when ready.` and no `--restart` CLI
flag. Resolving those runtime questions requires a separately authorized future
spike; this M0 must never restart the Mac.

## S8: remaining release-tag install

The locally completed part used MacPorts uv 0.13.4:

```sh
uv run --no-project --managed-python --python 3.14 python -c 'import curses,json,sys; print(json.dumps({"version":sys.version,"executable":sys.executable,"curses":True}))'
```

It downloaded managed CPython 3.14.8 and imported curses. This does not prove a
tool install chooses that interpreter or that the release tag is accessible.

The local packaging mechanics were subsequently tested with
`python3.14 tsr/scripts/m0-install.py`: a temporary git repository containing the
exact section 7 layout was committed and tagged locally, then installed using
`git+file://...@tag#subdirectory=tsr`. The installed entry point reported managed
Python 3.14.8 and curses. Its `TAGGED_V1` marker verified that uv used the tag,
despite a later uncommitted worktree edit. Scoped PATH lookup and uninstall also
passed. Tool/bin/cache directories were isolated and checked before installing.
The complete generated smoke files are visible in that script. This is a
packaging probe, not the production CLI or doctor.

The original SSH URL used a misspelled GitHub owner slug, so its
`Repository not found` response did not test the repository. The repository is
now public. Use the release install command in the project README to verify the
tagged subdirectory install and default-user PATH behavior.

On a Mac with MacPorts uv, run the following against the public release tag:

```sh
TSR_TEST_TAG=tsr-v0.2.0
uv --version
uv tool install --python 3.14 "git+ssh://git@github.com/million-views/tools@${TSR_TEST_TAG}#subdirectory=tsr"
uv tool list
command -v tsr
tsr --version
tsr doctor
TSR_TOOL_DIR=$(uv tool dir)
ls -l "$TSR_TOOL_DIR/tsr/bin/python"
"$TSR_TOOL_DIR/tsr/bin/python" -c 'import curses,json,sys; print(json.dumps({"version":sys.version,"executable":sys.executable,"curses":True}))'
```

`uv tool dir` returned the tools root on this machine. The proposed
`tsr/bin/python` path must be measured after installation: if it does not exist,
paste that error rather than running a different Python and claiming it proves
the tool's interpreter. That environment layout is part of this uncompleted
S8 test, not an assumed interface for tsr's implementation.

Paste command outputs and immediate exit codes, the installed interpreter report,
and whether the interpreter path is uv-managed. Replace account/home paths with
`/Users/USER`; preserve install-path structure, tag, versions and errors. Strip
any credentials from errors. A doctor warning because Ghostty is closed or no
snapshot exists must be distinguished from an installation failure.

If the install fails specifically on the subdirectory, document the failure before
considering a separate repository. If the installed managed Python cannot import
curses, the planned fallback is MacPorts `python314` and installation with
`--python /opt/local/bin/python3.14`. Do not select either fallback merely because
the prerequisite tag is absent.
