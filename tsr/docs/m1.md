# M1 implementation and verification

Historical milestone report. For current commands, tests and acceptance limits,
read [v1 verification](v1.md). The measurements below are the original M1 results.

M1 (`save` and `list`) was authorized by the owner's instruction to proceed after
the M0 status report. It is now implemented in `src/tsr/__init__.py`, with the
section 7 project layout, uv entry point and no runtime dependencies.

## Delivered behavior

- One batched Ghostty layout read, one ps read and one numeric-output lsof read.
  Running/version preconditions share the layout script. Native read-only boot
  time avoids a fourth subprocess (S12/F42).
- Ordered windows/tabs/panes; cwd fallback for terminals whose Ghostty property
  is empty; repository-based labels with stable ties and duplicate suffixes.
- Claude, Codex and pi adapters, including Claude's validated live registry,
  open-file evidence, validated command-text evidence, grouped recent-transcript
  matching and honest picker fallback.
- At most 200 transcript lines, with early stopping once identity/folder/prompt
  are available. Metadata-only records, tool results and system-tag context do
  not become the first prompt. Prompts are single-line and capped at 200 characters.
- Private state, staged writes, backup rotation and rollback after a failed
  current-snapshot replacement. If rollback itself fails, the old backup's secure
  staged file is retained for recovery. Failed captures leave both slots alone.
- Confirmation before replacing a snapshot from an earlier boot. `--yes` bypasses
  that confirmation only.
- Text inspection with manual recovery commands, JSON inspection, and previous
  snapshot inspection with `--backup`. Lists do not launch subprocesses.
- One-line runtime errors with private rotating tracebacks; debug tracebacks are
  opt-in. Configured state paths overlapping agent storage are rejected.

No terminal creation/input, agent launch, restart, project commit, release tag or
remote push was performed for M1. Live validation wrote snapshots only into an
isolated temporary XDG state root. Agent storage and Ghostty config stayed read-only.

## Verification

Both tested Python 3.14 installations passed the contract suite, including the
project's uv-managed Python 3.14.8:

```sh
PYTHONPATH=src python3.14 -m unittest discover -s tests -v
.venv/bin/python -m unittest discover -s tests -v
```

**17 tests passed.** They cover real M0 formats, end-to-end save/list, modes,
backup rotation and commit failure, stale-snapshot confirmation, precondition
failure preservation, live-registry precedence over stale argv, malformed
runtime records, old idle-resumed transcripts, picker fallback, safe pi paths
and custom session roots, prompt filtering/bounds, future/malformed snapshots,
outermost agent selection, recent candidate pairing and labels.

The first live test caught an AppleScript `tab` class/constant collision, fixed
by using ASCII character 9 as in the M0 probe. Profiling then identified layout
IPC as the bottleneck. S14 verified that bulk property reads preserve the stable
layout fields; S13 verified numeric lsof mode and its documented name-resolution
flags. No production behavior was inferred from a fake transport alone.

Final live result on the existing desktop:

| Check | Result |
| --- | --- |
| Capture | 11 windows, 62 tabs, 14 agent sessions |
| Save latency | **2.670 s** |
| Subprocesses | Exactly `osascript`, `ps`, `lsof` |
| Confidence | 11 exact Claude sessions; 3 likely Codex sessions |
| Backup | Previous current became the backup |
| JSON list | 0.0008 s; round-tripped the current ID |
| Backup JSON list | 0.0006 s; matched the prior current ID |
| Text list | 0.0010 s |
| List subprocesses | None |
| Snapshot modes | Both `0600` |

The aggregate report contains no real home paths, prompts or session IDs and was
previewed before saving as `tests/fixtures/m1-live-save.json`.

This live desktop exceeds the performance reference's pane count. It is not the
exact manual 3-window/9-tab acceptance fixture: Pi was not running during this
live capture, and Pi's contracts were exercised using its real M0 transcript.
Ghostty-not-running and Automation-denied behavior were tested through the fake
Runner without quitting or reconfiguring the owner's desktop. Independent
agent-reported ID checks for every reference session remain manual acceptance
work; do not report all v1 acceptance criteria as passed.

## Scope at the M1 milestone

Restore and doctor were not part of M1; they are now implemented. The later
spec decisions adopted scoped duplicate checks, deferred the Codex daemon query,
and preserved format-1 snapshots. See [v1 verification](v1.md) for current work;
the 17-test count and timings above are historical, not current totals.
